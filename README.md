# StreamUI

**0.1 / Windows x64** · [下载正式版 EXE](https://github.com/rorangeeee/StreamUI/releases/download/v0.1.0/StreamUI.Host.exe) · [Release 与更新说明](https://github.com/rorangeeee/StreamUI/releases/tag/v0.1.0)

本地直播视觉组件，按 `STREAMUI_v2_21-9.svg` 重构为 3840 × 2160 的 4K 直播版式。顶部左侧为紫底荧光绿的中英文标题与装饰，中部为黑底紫色循环品牌文字，信息终端位于品牌区右侧、字标下层；右上为单条弹幕与礼物展示。中间是全宽超宽透明主画面，底部左侧为声谱图，右侧为默认反色的示波器，页脚仅两条紫色跑马灯。输出与配置页的紫色统一为 TOYO82 `#40009E`，荧光黄绿统一为其严格 RGB 反色 `#BFFF61`；标题切换高光保留纯黑。六个区域的位置、尺寸、旋转、反色和层级由 Host 统一应用。

## 配置教程：以当前双布局模板为例

下面使用同一台 Windows 电脑运行 StreamUI Host、OBS 和 LAPLACE Chat。画布采用当前模板的 **3840 × 2160 / 60 fps**，并用 `STREAM_v2_34`、`STREAM_v2_27` 分别表示超宽场景和 16:9 场景。名称可以自行更换，在 StreamUI 中填写与 OBS 完全一致的名称即可。

### 1. 准备 Host 与字体

1. 从 Release 下载 `StreamUI.Host.exe`，放到固定目录，手动双击启动。GitHub 会把附件名里的空格规范化为点；本地正式包及下文命令示例使用 `StreamUI Host.exe`，下载后可另存为该名称，内容相同。它是自包含单文件程序，网页资源与 .NET 运行时均已内置，使用发布版无需安装 Node.js、编译源码或另外安装 .NET。
2. 配置页通常会自动打开，也可以访问 [http://127.0.0.1:5181/](http://127.0.0.1:5181/)。Host 驻留 Windows 系统托盘，可从托盘菜单打开配置页或退出。
3. 在「配置」中保留画布 `3840 × 2160`，设置中英文标题，并选择实际播放声音的 Windows 输出设备。保存后，在「预览」检查标题、频谱和波形。
4. 字体不包含在 EXE 中，需要自行在 Windows 中安装。标题、品牌与暂离条带主要使用 **Retro Pixel** 和 **405 SS 像素体**；页脚使用 **Blue Screen Personal Use**；弹幕使用 **JetBrains Mono** 与 **苹方 Thin**。装饰还使用 SF Pro、Technotot、Dot Matrix。字体缺失时会回退，外观会有差异。

各地址承担不同职责：

| 用途 | 本例地址 | 填写位置 |
| --- | --- | --- |
| StreamUI 配置页 | `http://127.0.0.1:5181/` | 主播的浏览器 |
| StreamUI 输出画面 | `http://127.0.0.1:5180/` | OBS 浏览器源的 URL |
| OBS WebSocket | `ws://127.0.0.1:4455` | StreamUI「场景自动切换布局」 |
| LAPLACE Event Bridge | `ws://localhost:9696` | StreamUI「LAPLACE 连接」 |

StreamUI 的两个 HTTP 端口只监听本机回环地址，因此本例要求 OBS 与 Host 同机运行。OBS WebSocket 密码和 LAPLACE Event Bridge Token 是两组独立的凭据，各自与对应服务匹配。

### 2. 在 OBS 建立两个场景

在 OBS「设置 → 视频」把基础画布设为 **3840 × 2160**，帧率设为 **60**。输出缩放分辨率可以根据推流需求选择 3840 × 2160 或 1920 × 1080；浏览器源仍使用模板的原始 4K 尺寸。

| OBS 场景示例 | 对应布局 | 下层视频源的摆放 |
| --- | --- | --- |
| `STREAM_v2_34` | 21:9 · 超宽主画面 | 超宽屏捕获或游戏源放入中央透明区域，默认约 `X=0、Y=276、宽=3840、高=1608`；例如 3440 × 1440 的画面可等比适配到这里 |
| `STREAM_v2_27` | 16:9 · 全画布叠加 | 屏幕捕获或游戏源等比铺满 3840 × 2160 画布 |

在 `STREAM_v2_34` 中添加一个「浏览器」源，命名为 `StreamUI Overlay`，按下面填写：

| 浏览器源属性 | 设置 |
| --- | --- |
| 本地文件 | 关闭 |
| URL | `http://127.0.0.1:5180/` |
| 宽度 / 高度 | `3840` / `2160` |
| 使用自定义帧率 | 开启，设为 `60` |
| 不可见时关闭源 | **关闭** |
| 场景变为活动状态时刷新浏览器 | **关闭** |
| 自定义 CSS | 保留 OBS 的默认透明背景设置 |

将 `StreamUI Overlay` 放到视频源上方，变换位置设为 `(0, 0)`，保持整张画布对齐。在 `STREAM_v2_27` 中通过「添加现有」选择同一个 `StreamUI Overlay`，继续放在视频源上方。这样两个场景共用同一个浏览器页面，转场时不会重新创建页面、重置动画或丢失弹幕历史。属性含义可参考 [OBS 浏览器源官方说明](https://obsproject.com/kb/browser-source)。

默认 21:9 布局的上下区域由网页铺黑，仅中央主画面透明；16:9 则让视频铺满画布，标题、侧栏、CHAT 与页脚覆盖在视频上。若保存过自定义布局，以 StreamUI 预览中的透明区域为准。直播声音继续由 OBS 的音频源采集；Host 的音频采集用于驱动可视化。

### 3. 配置 OBS 场景联动与延迟切换

1. 在 OBS「工具 → WebSocket 服务器设置」启用服务，使用端口 `4455`，记下连接信息里的密码。
2. 打开 StreamUI「配置 → 场景自动切换布局」，填写下表，点击「保存并应用」。
3. 确认状态变成「已连接」，并显示当前输出场景。连接失败时可查看具体失败阶段；修改地址或密码后先保存，再点「重新连接 OBS」。

| StreamUI 字段 | 本例填写 |
| --- | --- |
| OBS WebSocket 地址 | `ws://127.0.0.1:4455` |
| OBS WebSocket 密码 | 与 OBS 连接信息中的密码一致；OBS 未启用身份验证时留空 |
| 21:9 场景名称 | `STREAM_v2_34` |
| 16:9 场景名称 | `STREAM_v2_27` |

**两个场景名称都留空会关闭 OBS 监听**；只留空一个，则不自动进入该布局。工作室模式中，仅选择预览场景不会触发，真正执行输出转场时才触发。

OBS 侧选择一种在开始时立即触发转场、稍后切换实际画面的延迟转场方式。当前配置以「插入视频 / Stinger」为例：如果用它作为延迟器，视频素材应是全透明占位素材，时长需要长于切换点；StreamUI 的紫色转场动画由网页实时绘制。配置时间如下：

| 时间设置 | 数值 |
| --- | --- |
| 计时起点 | OBS 发出“转场开始”事件 |
| 网页完全遮住画面 | `1000 ms` |
| OBS 实际切画面 | **建议 `1100 ms`**；Stinger 选择按毫秒设置切换点 |
| 网页整段动画时长 | `7500 ms` |

已有的延迟转场插件也可以使用，关键是先开始转场、1100 ms 后再切画面。将整个切换命令延后执行，会同时推迟“转场开始”事件，达不到这个遮挡时序。发布包内没有 Stinger 视频文件；`transition.html` 是网页预览，不是视频素材。

设置完成后，在 OBS 中执行两场景之间的转场：应先看到紫色像素铺满，在被遮住时切换下层视频，然后看到隧道、组件重建及像素开屏。配置页手动选择布局可预览动画；实际 OBS 场景切换仍由 OBS 操作。更新 Host 后，手动刷新一次 OBS 浏览器源和配置页，以加载新版脚本。

### 4. 在 StreamUI 启动 LAPLACE Event Bridge

打开「配置 → LAPLACE 连接」，设置并保存：

| StreamUI 字段 | 本例填写 |
| --- | --- |
| 启用弹幕连接 | 开启 |
| Event Bridge 地址 | `ws://localhost:9696` |
| Token | 本机无鉴权时留空；使用鉴权时填写自己的桥接 Token |
| 由 Host 自动启动本地 Event Bridge | 开启 |

Host 会启动官方 Go 版桥接程序；首次下载需要联网。如果 9696 端口已有可用桥接服务，Host 会复用它，此时 Token 需要与已有服务匹配。连接成功只表示 Host 已接到桥接服务，接下来还需要让 LAPLACE Chat 页面提供直播间事件。相关机制见 [LAPLACE Event Bridge 官方文档](https://laplace.live/chat/event-bridge)。

### 5. 配置 LAPLACE Chat 页面

1. 用 Chrome 或 Edge 打开 [LAPLACE Chat](https://chat.laplace.live/)，按页面提示选择连接方式，并填写实际直播间 URL 或房间号。若使用幻星开放平台模式，按该模式要求填写身份码；需要完整昵称等信息时，按 LAPLACE 的说明配置自己的登录同步。
2. 在首页点击「打开控制台 / Open Dashboard」，进入该房间的采集控制台，先确认它能正常收到真实弹幕、礼物或醒目留言。首页右侧的演示数据不代表采集端已经连通。
3. 在控制台的设置中找到「Event Bridge 集成」，开启连接，填写：

   | LAPLACE 页面字段 | 本例填写 |
   | --- | --- |
   | 主机 / Host | `localhost`（也可用 `127.0.0.1`） |
   | 端口 / Port | `9696` |
   | Token | 与 StreamUI 的 Event Bridge Token 完全一致；本例无鉴权时两边都留空 |

   如果页面版本显示的是完整 WebSocket 地址字段，填写 `ws://localhost:9696`。这里的 Token 是桥接服务 Token，与 LAPLACE 登录同步密钥、OBS WebSocket 密码分别配置。

4. 保存或连接后，保持这个控制台页面运行。若浏览器询问是否允许访问本地网络，允许该页面连接本机服务。StreamUI 输出中的弹幕显示由本地浏览器源负责，LAPLACE 控制台负责采集并转发事件。
5. 如果当前版本将需要的入口放在实验功能里，可按 [Tech Preview 官方说明](https://laplace.live/chat/tech-preview)：打开控制台设置，找到底部的 `Powered by laplace.live` 分隔文字，连续点击 6 次切换实验模式，再查看设置入口。
6. 将 `chat.laplace.live` 加入浏览器的常驻站点名单，并把控制台留在独立、未最小化的窗口中，避免后台标签页休眠后停止提供事件。Chrome 可在「设置 → 性能」管理常驻站点，Edge 可在「设置 → 系统和性能」管理。更多说明见 [LAPLACE 控制台使用文档](https://laplace.live/chat/dashboard)。

LAPLACE 页面中的「OBS 集成」用于从控制台操作 OBS，和这里的 Event Bridge 是不同连接。本模板的场景联动由 StreamUI Host 完成；只接弹幕时，完成 Event Bridge 配置即可。

### 6. 验收与常见问题

依次检查以下现象：

1. OBS 的两套场景都能显示 StreamUI，中央视频区域透明且与捕获源对齐。
2. OBS 执行转场时，StreamUI 动画先开始，切画面后继续播放，不会重新从头铺像素。
3. 直播间出现真实消息时，LAPLACE 控制台收到事件，StreamUI 的「已接收事件」计数增加，最后在预览和 OBS 中显示。
4. 21:9 使用单条弹幕展示，16:9 使用滚动历史终端；无消息时只有光标属于正常状态。
5. 配置一段或两段暂离文字，保存后从配置页或托盘开启「暂离模式」，确认置顶条带与遮罩出现，退出后正常收回。

| 现象 | 检查方法 |
| --- | --- |
| OBS 显示配置界面 | 浏览器源 URL 应为 `5180`；`5181` 是主播配置页 |
| 画面被拉伸或透明区域错位 | 核对 Host 画布、OBS 基础画布和浏览器源尺寸；本例全部为 3840 × 2160 |
| OBS 已连接但不自动切布局 | 检查两个场景名称是否精确匹配、是否保存，以及是否真正切换了输出场景 |
| 转场未铺满就切了视频 | 核对延迟的起点是“转场开始”，实际切换点建议 1100 ms，并让浏览器源常驻 |
| Host 连接 Event Bridge 成功，但计数一直为 0 | 继续检查 LAPLACE 房间采集、页面的 Event Bridge 连接和后台休眠；桥接在线不等于已有采集事件 |
| LAPLACE 页面有消息，StreamUI 无消息 | 核对主机、9696 端口、桥接 Token 和 Host 的连接状态，观察事件计数是否增加 |
| 字体、排版与示例不同 | 安装模板使用的本机字体后刷新 OBS 浏览器源 |

升级时先退出旧 Host，再替换 EXE 并由自己启动。项目目录内运行会沿用 `.local/state/`；移到其他目录的单文件默认读取 `%LOCALAPPDATA%/StreamUI/`。如需迁移原配置，可使用 `--data-dir` 指向原数据目录，或把原数据目录完整复制到新 EXE 旁的 `.local/state/`；其中包含自己的连接凭据，请自行保管。

## 两套布局与 OBS 场景联动

配置页「预览」上方可手动选择 **21:9 · 超宽主画面** 或 **16:9 · 全画布叠加**。两者都使用同一套 3840 × 2160 画布、同一个 OBS 浏览器源地址；各自保留组件位置、尺寸、旋转、反色和层级。配置页目前仅保留「预览」和「配置」两个标签页，已移除可视化布局编辑及恢复默认布局入口，已有布局设置继续保留。已有 v3 布局继续作为 21:9 布局使用，不重置现有设置。

16:9 的视频铺满 OBS 画布，网页全画布透明，仅覆盖左侧紫色竖栏、顶部居中的中英文标题、右侧 CHAT 和两条页脚跑马灯。品牌及五组装饰按参考竖向排列。16:9 的标题使用字距收缩加横向模糊，侧栏品牌文字使用逐字拉伸加横向模糊；21:9 保持原标题拉伸、品牌收缩模糊的动效。切换布局时复用现有元素和播放时钟。中英文标题使用与 21:9 相同的基准字号及宽度适配基准，避免窄容器额外压小文字；短标题和长标题都围绕画布水平中心展开，保留原有垂直位置，过长文案仍自动适配宽度。已有 16:9 布局的标题也在显示时居中。标题和跑马灯保留现有颜色及高亮，新增无模糊的硬阴影；标题另有细小的反向硬边。声谱图、示波器、信息终端在这一套中隐藏。NOW PLAYING 使用原有实时组件，放到页脚上方居中；其曲目信息和动效仍由原组件维护。

16:9 的 CHAT 恢复长条滚动终端：连续保留最多 200 条消息，每条依次打印发送日期时间、用户名与等级、正文三行，礼物和 SC 使用紫底黑字卡片，恢复 CRT 扫描线、轻微文字辉光和闪烁光标。新消息自动跟随到底部，向上查看历史时保留阅读位置。外框、识别标签、终端文字和扫描线共用同一透视平面，约 10 秒为周期沿平面的 3D 深度方向轻微抬升，并伴随极小的俯仰；不沿画布 Y 轴平移。识别标签内的概率波动与分类跳变继续播放。页面隐藏时暂停，减少动态效果时跳过逐字打印并保持框体静止。21:9 继续使用原有的单条弹幕和礼物铺色组件；两者独立维护显示状态，切换回 16:9 时保留终端历史。

在「配置 → 场景自动切换布局」填写 OBS WebSocket v5 地址、密码及两套布局对应的场景名称，保存后由 Host 监听实际输出场景。默认地址为 `ws://127.0.0.1:4455`，需要在 OBS 的「工具 → WebSocket 服务器设置」启用服务。场景名称精确匹配；某一名称留空时，不自动切换到该布局，两项都空时停止监听。其他场景保持当前布局；工作室模式的预览切换不触发。连接成功或断线重连后会读取当前输出场景。密码仅保存在本机设置中，不发送到 OBS 展示页。

监听采用[官方 OBS WebSocket v5 协议](https://github.com/obsproject/obs-websocket/blob/master/docs/generated/protocol.md)，订阅场景、配置和转场事件，只读监听，不修改 OBS 场景或视频源。`SceneTransitionStarted` 立即启动网页转场，随后 `CurrentProgramSceneChanged` 在同一条时间轴上确定目标布局；`SceneTransitionEnded` 和 `SceneTransitionVideoEnded` 只确认状态并重新读取输出场景，不重播动画。转场开始不携带目标场景，因此在场景变更之前先播放公共遮罩；未匹配的输出场景保留当前布局。设置使用 `layoutMode` 和 `layoutProfiles` 保存两套布局；编辑保存附带所属布局，避免场景切换时迟到的保存覆盖另一套布局。

OBS 延迟转场建议在开始后 **1100 ms** 切换实际画面：网页在 **1000 ms（60 fps 的时间轴位置 60）** 完全铺满，额外 100 ms 用于本机事件传递与首帧绘制。整个网页转场为 **7500 ms**，不要把延迟切换时间设成动画总时长。两套 OBS 场景复用同一个浏览器源并保持常驻，避免切换时销毁、刷新页面。Host 会为每次 OBS 转场分配共享 ID 和开始时间；预览、输出页和中途恢复可见的页面按同一时钟续播。断线重连清除旧事件，过期的转场不会重播。

连接状态会区分连接、协议握手、密码验证和读取输出场景；只有取得实际场景才显示已连接。握手超时为 10 秒，场景请求超时为 5 秒，空闲时每 10 秒发送一次只读健康检查。已建立但不再响应请求的连接会自动断开并在 3 秒后重试。协议错误（包括 `InvalidDataException`）也进入重连分支，避免监听任务直接退出后卡在连接中。配置页「重新连接 OBS」可使用已保存的地址和密码立即重连；修改设置后先保存。错误信息显示具体失败阶段，旧连接被取消后不会覆盖新连接的状态。

隔离实例的联动集成检查：`node scripts/test-layout-obs.mjs http://127.0.0.1:5241`。测试使用本地模拟 OBS，覆盖密码握手、两套场景匹配、空名称、预览场景、断线重连及过期保存。`tests/wide-layout-check.html` 为独立浏览器验证页，不进入正式构建。

仅验证 OBS 连接客户端（不启动 Host、网页服务或托盘）：`node scripts/test-obs-connection.mjs`。覆盖不回包、持续收事件但 RPC 失效、握手与鉴权超时、密码错误、取消旧连接、过期场景响应和恢复重连。

## 布局转场与网页预览

配置页「预览」中切换 21:9 / 16:9 布局时，会在实时画面中播放完整 7.5 秒转场；OBS 输出及场景自动切换布局也使用同一套动画。前 1 秒保留旧布局，由随机紫色像素逐步覆盖；画面完全遮住后切换布局，再依次形成分割线与实时组件，最后露出透明主画面。转场保留原有弹幕历史、曲目信息及组件状态，使用当前保存的布局、画布尺寸和标题。

首次打开页面直接显示当前布局，不播放开场转场；如果 OBS 正在转场，则加入当前动画进度。重复选择同一布局及普通状态更新不会重播。手动预览中，像素铺屏阶段切回原布局会取消转场，遮罩后的连续切换先完成当前动画，再转到最新请求的布局。OBS 连续开始新的转场时，网页跟随新的开始事件。页面隐藏、系统启用「减少动态效果」或转场中修改画布尺寸时，直接落到最新布局并清除遮罩；页面恢复可见时，若 OBS 转场尚未结束则从共享时钟续播。

启动开发服务 `npm run dev` 后，打开 `http://127.0.0.1:5173/transition.html`。这是独立的透明网页动效，支持进入 21:9 和进入 16:9 两个版本；点击「从头播放」观看完整 7.5 秒转场，可暂停、拖动时间轴或逐阶段查看，支持循环预览。棋盘格只用于标示透明区域。

转场按「随机紫色像素铺屏 → RESCALING 双闪并转黑 → 荧光黄隧道矩形由大到小错峰双闪出现，同时紫底渐暗为黑，黑色 RESCALING 同步淡出 → 隧道从缓慢推进到末段猛加速 → 分割线与组件依次形成 → 主画面黑色大像素随机消失」播放，总时长 7.5 秒。隧道推进段延长至 2.2 秒，前段缓行、后段速度陡增，文字在背景变黑时完全消失。画布默认 3840 × 2160，网格为约 300 px 方块，开头 1 秒铺满、末尾 1 秒逐块消失；本机安装的 Retro Pixel 用于 RESCALING。隧道阶段没有全屏荧光黄闪光，最后的像素遮罩位于实时组件下方，仅遮住屏幕捕获区域；组件保留原有颜色并错峰双闪，像素完全消失后恢复透明主画面。

独立预览默认使用项目布局与标题，可点击「读取当前 Host 的布局与标题」只读载入现有配置。独立预览不会启动音频采集或弹幕连接，也不修改 Host 设置。它与直播画面共用 `src/transition-renderer.ts`、`src/transition-effects.css` 和 `src/transition-model.ts`；实时切换时序由 `src/transition-playback.ts` 管理，独立页保留暂停和逐帧检查功能。转场已纳入前端构建，未导出视频。

## 暂离模式

在配置页「配置 → 暂离提示」填写两段文字并保存。第一段必填，每段最多 500 个字符；第二段留空时，只显示第一段和一个分隔块。填写两段时按「文字 1 → 黑色斜线长条矩形 → 文字 2 → 黑色斜线长条矩形」连续向左无缝滚动。文字沿用中英文标题的 Retro Pixel 和 405 SS 像素字体，分别按实际字面高度校准字号；4K 下实字高约 128 px，比原标题更醒目，不直接沿用标题字号。

配置页「预览」和「暂离提示」内都有即时生效的「暂离模式」开关；托盘右键菜单也有同名开关和勾选状态。三处共用 Host 保存的状态，切换后同步到预览与 OBS。开关使用独立接口，迟到的设置表单不会覆盖刚从托盘切换的状态。文字与遮罩设置仍通过「保存并应用」保存。

开启时，画布垂直中心的 4 px 紫色细线先用约 640 ms 从左向右铺满，再用约 680 ms 向上下展开成 256 px 高的条带，随后淡入文字并以约 180 px/s 滚动。退出时先收缩为细线，再从左向右移出。展开、收缩和线条移动使用 `cubic-bezier(.7, 0, .3, 1)` 慢—快—慢曲线；快速重复切换会从当前形态连续衔接。所有尺寸与速度随画布等比缩放。

暂离条带位于实时组件和布局转场上方；它下方的整个画布覆盖渐显、渐隐的黑色遮罩，包含原本透明的屏幕捕获区域。默认不透明度为 50%，可设置为 0%–100%（0% 不遮暗，100% 全黑）。页面隐藏时暂停滚动，恢复后继续；启用「减少动态效果」时直接显示静态条带。Host 重启或重新打开页面会保留已保存的暂离模式与文字，已开启时直接恢复提示。

## 运行

日常使用直接双击项目根目录的 **`StreamUI Host.exe`**。程序内置 Windows x64 运行时和网页资源，无需终端、Node.js 或另装 .NET。启动后显示 StreamUI 托盘图标，并打开配置页；Windows 可能把图标收在任务栏右下角的「隐藏图标」中。

功能修改完成后默认只打包 EXE，由使用者手动启动；不自动启动或重启 Host。根目录交付的单文件包可脱离源码单独运行，配置保存在数据目录，自定义字体依赖目标机器安装。`.local/host` 等开发构建可能仍依赖外部 .NET 运行时，不等同于交付的自包含单文件包。

托盘右键菜单提供「启动服务」「停止服务」「重启服务」和「退出 StreamUI Host」。停止服务会关闭音频、LAPLACE 连接及两个网页端口，保留托盘图标；再次启动或重启后，OBS 和配置页自动重新连接。双击托盘图标会启动服务并打开配置页。重复双击 EXE 会激活现有实例，不会重复采集音频。

从源码构建需要 Node.js 和 .NET 10 SDK：

```sh
npm install
npm run host:package
npm run host
```

- OBS 浏览器源：<http://127.0.0.1:5180/>，默认画布 **3840 × 2160**。
- 独立配置页：<http://127.0.0.1:5181/>。
- Host 在 Windows 系统托盘驻留；右键还可打开 OBS 画面、配置登录自启。关闭浏览器不停止采集。
- 配置页的「预览」显示输出并支持切换两套布局；「配置」选择真实 Windows 输出设备、声道、可视化增益，并设置 LAPLACE 地址、Token 和画布尺寸。
- 「配置 → 中英文标题」分别填写英文和中文文案，每行一段，在同一位置按「英文 1 → 中文 1 → 英文 2 → 中文 2」交替，使用纯横向模糊切换。两种语言的段数不同时，各自按顺序循环；默认 `TITLE → 标题`。保存后立即同步到预览与 OBS。
- 首次升级到 v3 时，将旧设置备份为 `settings.json.before-layout-v3-*`，切换到新默认布局；保留音频、LAPLACE、中英文标题及 v2 自定义画布尺寸，后续启动继续保留已保存的新布局。
- `npm run host` 使用 `.local/state/settings.json` 保存配置和布局。根目录 EXE 会沿用现有 `.local/state/`；将单个 EXE 复制到其他位置后，默认使用 `%LOCALAPPDATA%/StreamUI/`。网页资源自动解压到数据目录的版本缓存，更新后使用新版缓存。登录自启保留当前端口和数据目录，默认关闭，可在配置页或托盘菜单中启用。
- 更新构建前先从托盘退出 Host，再执行 `npm run host:package`，生成根目录的 `StreamUI Host.exe`。首次打包从微软的 NuGet 源获取运行时，缓存于 `.local/nuget-packages/`。`npm run host:build` 仍提供较小的开发版本，发布到 `.local/host/`，需要本机安装 .NET 10 Desktop Runtime / ASP.NET Core Runtime。

两个 HTTP 端口只监听本机回环地址。OBS 端口仅提供展示和数据流，修改配置与布局必须通过配置端口。音频采集在 host 中自动启动，不需要 OBS 或浏览器获得音频、屏幕共享权限。

自定义启动参数示例：

```powershell
& '.\StreamUI Host.exe' --obs-port 5180 --config-port 5181 --data-dir D:/StreamUI/.local/state
```

开发时保持 host 运行，再启动 Vite（5173 的音频和事件请求代理到 host）：

```sh
npm run dev
```

配置页请使用 host 的 5181 端口。`npm run build` 只构建前端；`npm test` 验证动画、几何、音频协议与布局数据；`npm run host:test` 验证原生 FFT、WASAPI 设备枚举及 host HTTP / WebSocket 链路。

启用「自动启动本地 Event Bridge」后，host 首次下载官方 Go 版 0.3.21 并校验 SHA-256，之后离线复用；如果已有服务监听 `localhost:9696`，直接连接，不接管其生命周期。首次启动需要联网或已有校验通过的缓存。原 `npm run bridge` 仍可单独使用。

## 直播弹幕

在配置页设置 Event Bridge 地址和 Token；默认由 host 管理 `ws://localhost:9696`。在 LAPLACE Chat 的「Event Bridge 集成」中填写主机 `localhost`、端口 `9696`，Token 与配置页一致，并保持采集端运行。若连接已有远程桥接，关闭自动启动，填写其 `ws://` / `wss://` 地址。

Host 统一连接 Event Bridge，处理心跳和断线重连，再把 `message`、`gift`、`superchat` 事件转发到 OBS 和预览页。浏览器不直接连接 LAPLACE，也不接收 Token。连接状态及事件计数显示在配置页；弹幕采集与音频采集相互独立。

21:9 布局中，普通弹幕一次显示一条，恢复发送日期时间、用户名和正文。日期时间使用原事件的标准化发送时间，按浏览器本地时区显示为 `YYYY-MM-DD HH:mm:ss`。正文约 10 ms/字，最长打字时间约 1.2 秒，保留完整 emoji 字形；打印后停留约 2.2 秒再显示下一条，繁忙时缩短停留，最后一条保持显示。长正文自动折行，仅正文区域跟随打印内容滚动。

礼物优先展示：先用约 450 ms 将紫色从左向右铺满 CHAT，完成后依次打印两行黑字「用户名」「送出[礼物名]」，行间约 160 ms。完成后停留约 3.2 秒，再用约 350 ms 收回背景，恢复被打断的普通弹幕。连续礼物独立排队；SC 使用同一强调流程，保留「用户名」「[¥金额] 留言」两行，停留约 4.5 秒，金额取 `priceNormalized`。

英文字体使用本机 JetBrains Mono，中文使用苹方 Thin。4K 下正文 40 px、用户名 36 px、日期时间 28 px，保留轻微辉光、闪烁光标及每 3 px 一条的细扫描线；长正文在独立区域内滚动，用户名和日期时间固定可见。普通弹幕最多缓存 200 条，重复事件去重；任一时刻只存在一条展示内容。页面隐藏时暂停显示动画，启用「减少动态效果」时跳过铺色与打字动画，保留阅读停留和单条切换。

接入遵循 [官方 SDK 的 WebSocket 协议](https://github.com/laplace-live/event-bridge/tree/master/packages/sdk)，字段以 [事件类型定义](https://chat.laplace.live/event-types/) 为准；[接入文档](https://laplace.live/chat/event-bridge)。

## 操作

标题栏右上方的 DSGND BY WHEN 改为横排，使用原有 Technotot 字体。13 个字符槽位（含两个空格）偶发地按无重复随机顺序逐个替换成等大的黑色方块，每步约 80 ms；全部变块后保持 500 ms，再按另一组随机顺序逐个恢复。空格保留完整槽位，变换过程不重新排版。首次等待约 6–14 秒，后续每次完成再等待约 12–28 秒。页面隐藏时暂停，启用「减少动态效果」时显示完整原文。

标题栏右上定位标志保留 SVG 的圆心、比例及贯穿圆心的两条 X 笔画。圆环以约 5.2 秒为周期呼吸；X 持续以 5°/s 转动，并以独立的约 13.7 秒周期平滑加速至 40°/s 后回落。每笔擦除与显现各约 1.6 秒，均沿同一端到另一端使用慢—快—慢曲线；第二笔延迟随机 0.8–1 秒。切口为硬边界实线，使用平头端点。三组动效独立计时，页面隐藏时暂停，启用「减少动态效果」时显示静态完整标志。

标题栏左下条码改为编码 `LATENITE` 的有效 Code 128 B，包含起始符、校验符、停止符和左右静区，由 34 根独立 SVG 竖条绘制。首次等待约 6–16 秒，随后从左到右每 35 ms 消失一条，全部消失后停留 450 ms，再从左到右逐条恢复，完成后等待约 12–28 秒再次触发。独立随机双闪使用 TOYO82 紫的严格反色 `#BFFF61`，亮 80 ms、黑 80 ms、再亮 80 ms，随后恢复黑色。页面隐藏时暂停，启用减少动态效果时显示静态黑码。

标题栏右下 Data Matrix 为内容 `LATENITE` 的有效 ECC200 码图，14 × 14 个模块，在 4K 默认布局中以 28 × 28 px 绘制。常态黑码，空白处透出紫色标题栏。以左下为 `(0,0)`，按 `x+y` 递增的斜行顺序每 60 ms 填黑一批空白模块，全部填黑后保持 1 秒，再按同一顺序恢复，恢复后停留约 1.6 秒继续循环。荧光黄绿用于独立随机触发的故障双闪：亮 80 ms、黑 80 ms、再亮 80 ms，随后恢复黑色，下一次等待约 12–26 秒。页面隐藏时暂停；启用「减少动态效果」时显示静态黑码。

左上 ON AIR 使用本机的 SF Pro 可变字体。O 固定为 1000 字重、字宽 100%，中心以同色实心圆填满，保持位置和尺寸不变；黑色与暗红色 `#8a1024` 每 800 ms 交替。N AIR 的字宽在 70%–135%、字重在 150–850、倾斜角在直立至右倾 12° 之间往返变化，三项均为 8 秒完整周期，字重和倾斜分别错开 1.1 秒、2.3 秒，使用同一条慢—快—慢曲线。SF Pro 没有倾斜轴，倾斜由保持基线固定的字形变换实现。页面隐藏时暂停；系统启用「减少动态效果」时显示静态暗红 O 与正常字宽、200 字重的文字。

顶部品牌区横排字标按 `LATENITE → NOIZBOIZ → HOPEFINDERS → BASSKARYOTES` 自动播放，使用本机 Retro Pixel 字体，常态为紫色。每个词停留 1.8 秒，转场约 1.6 秒，整轮约 13.6 秒。字形保持正常宽高，改用纯横向模糊切换，峰值为 48 SVG 单位标准差，字距向中心收紧至 55%；常态紫色和原有反色高亮保持不变。

中英文标题在左侧紫色标题栏中心交替，共用原有播放时钟和 1600 ms 转场曲线，每段停留 6900 ms、切换间隔 8500 ms。切换改为逐字横向拉伸至 9 倍，叠加与品牌文字一致、峰值 48 SVG 单位的横向模糊，纵向为零，静止时移除滤镜。字距在切换中点收紧到 75%，左右两端围绕共同中心收拢，再向两侧展开；常态荧光绿，切换高光使用纯黑 `#000000`。英文使用 Retro Pixel，基准字号 115 px；中文使用 405 SS 像素体，基准字号 100 px，共用一条基线。长标题和较小的标题容器自动等比缩小，保持中心锚点。字体取自本机安装，缺失时使用后备字体。

页脚仅保留两条独立的无缝跑马灯，使用 Blue Screen Personal Use 字体。上条感谢文字向右 64 px/s，下条提示文字向左 40 px/s，速度按画布等比缩放。两条常态均为紫色 `#40009e`；各自随机触发泛光时，文字及光晕随同一条强度曲线同步渐变到反色荧光绿 `#bfff61`，退光时同步恢复紫色。泛光先用 900 ms 渐亮，峰值短暂停留 160 ms，随后同步双闪两次（每次熄灭 50 ms、亮起 60 ms），最后用 1200 ms 渐暗。闪烁期间高亮与光晕同时熄灭、同时恢复，普通紫色文字持续可见。首次独立等待约 4–16 秒，之后每次结束再独立等待约 12–36 秒；效果不改变滚动方向、速度或循环进度。页面隐藏时暂停滚动、泛光及倒计时，启用「减少动态效果」时静止并关闭泛光。

主画面与 CHAT 的标签位置固定，已移除框体颤动及各区域的封闭外框。仅保留标签内容变化：概率分别在 0.79 / 0.64 附近小幅波动，偶尔大幅跳变后于约 1–1.6 秒恢复；分类文字偶尔短暂变为 LATENITE / NOISE / NULL / ERROR，再恢复 STREAMING / CHAT。效果不改变窗口位置、尺寸或保存的布局。页面隐藏或启用「减少动态效果」时暂停。

所有区域均移除独立外框和自身边线，改由独立 SVG 图层统一绘制四组开放分割线：直播主画面上边、下边，声谱图与示波器之间的竖线，以及两音频区域的底线。所有线条统一使用紫色，线宽以 4K 中的 4 px 为基准，不受示波器反色影响；几何随各区域移动、缩放和旋转，画布左右外沿不画框。

跑马灯的颜色交叉渐变和两色光晕使用预先绘制的独立图层，只动画化 opacity；两层光晕在独立的 plus-lighter 混合组内叠加，保证峰值完全变绿，退光后无残留。滚动仍使用 3D transform，避免逐帧重新绘制模糊文字。

信息终端位于黑底品牌区右侧，局部层级低于品牌文字，随品牌区域一起移动、缩放和旋转。使用本机 Dot Matrix 常规字体，默认约 499 × 236 px，14 px 字号，保留 14 行信息。文字、三层光晕和光标均为纯白基准、整体 10% 不透明度。

拉伸转场共用 `cubic-bezier(.7, 0, .3, 1)` 曲线：旧字逐字横向延展至 9 倍，在速度最快的中点跳切到新字，随后立即回缩，跳切处不重新起缓动。字高不变，字距最多收紧至 75%，高亮在最大字宽的 80%–100% 区间连续渐入渐出。新版横向显示，页面隐藏时暂停，启用「减少动态效果」时显示静态首段。

- 配置页预览与 OBS 输出页均用于展示，位置、尺寸、角度、反色状态和层级由 host 统一应用；坐标按画布归一化。
- 需要停止音频时，在配置页关闭「启用桌面音频采集」并保存；重新启用后自动恢复，无需授权。

OBS 输出包含标题、品牌文字、装饰、区域分割线、STREAMING / CHAT 竖标签及两条页脚文字带。信息终端每 40 ms 打印一个字符，完成后停留 1.1 秒，直接跳切上移一行；开场保留 13 行历史，循环后始终只保存 14 行。画布尺寸、帧率、直播间、赞助、日期时间、采集方式、音频格式、FFT 与 LAPLACE 状态持续循环。每行预留完整文本宽度，避免逐字打印时左右移动。页面隐藏时暂停，启用「减少动态效果」时显示静态完整行。

没有音频时声谱图为空、波形为基线；无弹幕时 CHAT 仅显示闪烁光标。主画面内部透明，仅保留分割线与标签；在 OBS 中将本页浏览器源放在视频或游戏源上方。透明区域随保存的布局应用位置、尺寸和旋转。配置页预览使用棋盘格显示透明区域。

浏览器的实际 GPU 加速由 OBS 的浏览器硬件加速设置及显卡驱动控制；网页使用合成图层动画。循环字标在停留阶段跳过重复 DOM 更新，ON AIR 省略无视觉差别的更新；音频图表只在收到新帧时绘制，颜色在主题变化时缓存更新。

## 自动曲目显示

Host 只读 Windows 系统媒体会话，自动选择正在播放且提供标题的会话，每秒更新歌曲名和歌手；不提供手动填写。播放器暂停、关闭或没有可用曲目时，NOW PLAYING 整段隐藏。配置页「当前曲目」只读显示检测状态。该功能需要播放器向 Windows 上报系统媒体信息。

频谱区中央显示 `NOW PLAYING:  [歌曲名]-[歌手]`（冒号后两个空格）。英文使用 Retro Pixel，中文使用 405-上首像素体；英文保留约 42 px 的 SVG 参考字高，对应默认频谱区 218.615 px 高度。加载字体后按实际可见像素校准中文字号，使中英文的字形等高并垂直居中，避免 SVG 文本框中的字体留白让中文显得偏小。长曲名整体等比适配宽度，保持居中。

文字为 TOYO82 紫 `#40009E`。21:9 中直接覆盖在频谱图案上，不使用差值混合，并添加按画布缩放的 2 px 黑色硬阴影；16:9 保留原有差值混合。每 800 ms 亮灭一次，与 ON AIR 的 O 周期相同；灭时直接隐藏文字与阴影。页面隐藏时暂停，系统减少动态效果时保持常亮。读取进程随 Host 服务启动和停止，不控制播放器。

## 音频与绘图

Host 使用 [WASAPI loopback](https://learn.microsoft.com/en-us/windows/win32/coreaudio/loopback-recording) 获取所选 Windows 输出设备的系统混音，可跟随默认设备或固定到某个设备，支持混合所有声道或选择单个声道。设备断开时自动重试；默认输出变更时自动切换。采集在独立 MTA 线程进行，停止或切换设备会释放原音频流。

Host 通过 Windows 音频引擎的采样率转换固定接收 **48 kHz** 音频流，保留设备的原生声道布局，不改变声卡的系统采样率设置。即使输出设备工作在 384 kHz，可视化仍使用 48 kHz；8192 点 Blackman FFT 的频率间隔固定约 **5.86 Hz**，避免高采样率让可听频段的细节减少。平滑系数为 0.72，使用高精度等待计时器按 **60 fps** 推送频谱和波形，不依赖 Windows 粗粒度的轮询超时；配置页显示原生设备采样率、可视化采样率和实际帧率。FFT 旋转因子和窗函数预先缓存，减少逐帧计算。

二进制协议为 16 字节小端头部（`SUIA`、采样率、4096 个频点、8192 个波形点），随后为 float32 频谱 dB 和波形。客户端会丢弃损坏或包含非有限数值的帧；慢客户端只保留最新帧，避免积压。静音时补零，避免冻结在最后一帧。

声谱图横轴为时间（48 px/s，最新数据在右侧），纵轴为对数频率（下方低频，上方高频，30 Hz 至 20 kHz 或奈奎斯特频率），亮度表示强度。波形带上升零交叉触发，最多显示当前 8192 点中的约 45 ms。

音频仅在本机采集和分析，不录音、不上传、不回放；不会把桌面声音重复播放到扬声器或 OBS。浏览器不创建 AudioContext，不调用 `getDisplayMedia` / `getUserMedia`。OBS 的声音输出仍使用其常规音频源。Host 或网络连接重启后，页面自动重新连接。
